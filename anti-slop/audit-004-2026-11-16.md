## 1. Security Architecture Findings (`#S9` - `#S14`)

### S9 [HIGH] Missing Origin Enforcement & Unconstrained `https://` Allowlist in `OursNativeBridge.kt`
- **Locations**: `android/app/src/main/java/app/ours/bridge/OursNativeBridge.kt`, `android/app/src/main/java/app/ours/data/local/PrefsStore.kt`
- **Finding**:
  - `getNativeState()` checks `isTrustedOrigin()`, whereas `@JavascriptInterface` methods `syncAuth()`, `setServerUrl()`, `reloadUpdatingUi()`, `hapticTick()`, and `signInWithGoogle()` do not enforce `isTrustedOrigin()`.
  - `isTrustedServerUrl()` returns `true` for any `"https"` URL (`"https" -> true`). Any script able to call `setServerUrl("https://attacker.example")` shifts `prefs.serverUrl`, triggering `onReloadFromServer` and automatically trusting the new origin for `getNativeState()` token exfiltration.
- **Remediation**:
  - Enforce `isTrustedOrigin()` inside every `@JavascriptInterface` method (`syncAuth`, `setServerUrl`, `reloadUpdatingUi`, `hapticTick`, `signInWithGoogle`, `getNativeState`).
  - Tighten `isTrustedServerUrl()`: permit HTTPS URLs on `ours.mnemonic.my.id`, `BuildConfig.DEFAULT_SERVER_URL` host, or explicit user-configured self-hosted HTTPS hosts only when called from an already-trusted origin with a valid hostname (no credentials/userInfo, no IP-literal HTTP in release); restrict cleartext `http://` (`127.0.0.1`, `localhost`, `10.0.2.2`, RFC1918 LAN / `100.64.0.0/10` Tailscale) to debug/explicitly permitted dev paths without hardcoding `trycloudflare.com` tunnels.
  - Gate `PrefsStore.serverUrl` dev-host filtering with `!BuildConfig.DEBUG` so debug builds can test `http://10.0.2.2:18787` cleanly while release builds reject leftover dev URLs.

### S10 [MEDIUM-HIGH] WebView File/Content Access, Native Google Callback Escaping & Status Bar Theme Sync
- **Locations**: `android/app/src/main/java/app/ours/ui/screens/OursWebShellScreen.kt`, `android/app/src/main/java/app/ours/MainActivity.kt`
- **Finding**:
  - `OursWebShellScreen.kt` sets `allowFileAccess = true` even though `file:///android_asset/` loads with `allowFileAccess = false`, and leaves `allowContentAccess` at default (`true`).
  - Google auth callback injection via `evaluateJavascript` duplicates JSON construction in two call sites and does not check `isTrustedUrl(webView?.url)` before evaluating JS.
  - `MainActivity.kt` drives `isAppearanceLightStatusBars` / `isAppearanceLightNavigationBars` solely from `isSystemInDarkTheme()` rather than observing `PrefsStore.themeMode`, allowing dark `#splash` or explicit dark/light toggle to mismatch status bar icon contrast.
- **Remediation**:
  - Set `allowFileAccess = false` and `allowContentAccess = false`.
  - Extract a single `dispatchGoogleAuthResult(...)` helper guarded by `OursNativeBridge.isTrustedUrl(webView?.url, prefs.serverUrl)` and `JSONObject.quote(...)`.
  - Register `SharedPreferences.OnSharedPreferenceChangeListener` in `MainActivity.kt` so Android system bars track `prefs.themeMode` (`light` / `dark` / `system`) immediately.

### S11 [HIGH] Access Tokens (`1h` TTL) Remain Valid After `POST /api/auth/logout`
- **Locations**: `server/src/auth.rs`, `server/src/db.rs`, `server/src/routes/pair.rs`, `server/src/ws.rs`
- **Finding**:
  - `AccessPayload` contains only `uid` and `exp`. Calling `POST /api/auth/logout` revokes `refresh_tokens` and disconnects existing WebSockets, but an active `access_token` continues authenticating REST endpoints and opening new `/api/ws` connections until its 1-hour expiry.
- **Remediation**:
  - Add `iat_ms: i64` to `AccessPayload` and column `tokens_revoked_before INTEGER NOT NULL DEFAULT 0` on `users` in `db.rs`.
  - `issue_tokens()` issues `iat_ms = now_ms().max(revoked_before + 1)` cleanly inside the same transaction.
  - `logout()` sets `tokens_revoked_before = now_ms().max(current_revoked_before)` (and cleans all refresh tokens + WS sessions).
  - `AuthUser` extractor and `ws_handler` verify the token's user exists and `iat_ms > tokens_revoked_before`, rejecting post-logout access tokens with `401 Unauthorized`.

### S12 [HIGH] Missing HTTP `Origin` Check on WebSocket Upgrade (CSWSH Defense) & Query Token Leakage Mitigation
- **Locations**: `server/src/ws.rs`, `web/app.js`
- **Finding**:
  - `ws_handler` upgrades any WebSocket regardless of the HTTP `Origin` header.
  - Browser WebSocket client passes JWT in `?token=...`, writing bearer tokens to reverse-proxy access logs when HTTP subprotocol/header auth could be used.
- **Remediation**:
  - Validate the HTTP `Origin` header in `ws_handler` when present: allow matching authority host against `Host` / `X-Forwarded-Host`, allow Android WebView offline `file://` (`Origin: file://`) and loopback dev hosts (`127.0.0.1`, `localhost`, `10.0.2.2`), and reject untrusted third-party web origins (`https://evil.example`) with `403 Forbidden`.
  - Support `Sec-WebSocket-Protocol` (`ours.v1`, `bearer.<token>`) in `ws_handler` (echoing `ours.v1` subprotocol cleanly) and update `web/app.js` `connectWebSocket()` to send the token via `Sec-WebSocket-Protocol` instead of query params while retaining `Authorization: Bearer` for native OkHttp clients.

### S13 [HIGH] Client-Spoofable IP Headers in Auth & Pair Rate Limiting (`client_rate_key`)
- **Locations**: `server/src/routes/pair.rs`, `server/src/main.rs`
- **Finding**:
  - `client_rate_key` blindly trusts `CF-Connecting-IP`, `X-Real-IP`, and `X-Forwarded-For` from any caller, allowing attackers hitting the server directly (or forging headers where unstripped) to rotate fake IP strings on every request and bypass brute-force locks on `create_pair`, `join_pair`, `refresh_auth`, and `google_auth`.
- **Remediation**:
  - Extract optional peer `SocketAddr` via `ConnectInfo<SocketAddr>` (configured via `into_make_service_with_connect_info` in `main.rs`, with safe non-panicking fallback if absent in direct router tests).
  - Only honor forwarded IP headers (`CF-Connecting-IP` / `X-Real-IP` / first hop `X-Forwarded-For`) when the direct TCP peer is loopback or link/private trusted proxy; otherwise key strictly on the peer IP.
  - Additionally enforce normalized per-email and global key buckets in `google_auth` / `join_pair` / `create_pair` so rotating source IPs cannot brute-force a specific target email or 6-character invite code.

### S14 [MEDIUM] Client Logout Cleanup & Modal Async Error Boundaries (`web/app.js`)
- **Locations**: `web/app.js`
- **Finding**:
  - `btn-logout` does not close active `state.waitingSocket` or revoke cached `PHOTO_CACHE` `blob:` URLs in memory before resetting state.
  - `openPlacesModal()` `add`/`delete` actions lack `try/catch` and busy disabled state during async `apiFetch`.
- **Remediation**:
  - Extract `resetClientSession()` closing WS cleanly, revoking all `PHOTO_CACHE` object URLs, and resetting partner/message/checkin/memory/event caches.
  - Guard place create/delete buttons with `try/catch` and loading feedback.

## 4. Bugs Discovered & Fixed During Live E2E Testing + FigCraft Alignment

1. **Android DayNight vs WebView `(prefers-color-scheme: dark)` Mismatch (`themes.xml`, `values-v31/themes.xml`)**:
   - **Root cause**: Default Android styles inherited `android:Theme.Material.NoActionBar` (dark theme) while `Night mode: no` was active, causing Chromium WebView to match Dark Obsidian CSS while Compose painted dark status-bar icons on top.
   - **Fix**: Switched day `themes.xml` and `values-v31/themes.xml` to `android:Theme.Material.Light.NoActionBar` while keeping `values-night` on `NoActionBar`.

2. **Edge-to-Edge Status Bar Overlap on Settings & Memories Headers (`OursWebShellScreen.kt`, `OursNativeBridge.kt`, `web/styles.css`, `web/app.js`)**:
   - **Root cause**: `enableEdgeToEdge()` extended WebView behind system bars while Android WebView resolved `env(safe-area-inset-top)` to `0px`.
   - **Fix**: Exposed `WindowInsetsCompat.Type.systemBars() | displayCutout()` (`safeTopPx`, `safeBottomPx`) through `OursNativeBridge.getNativeState()` and `ViewCompat.setOnApplyWindowInsetsListener`, updating `--safe-top` and `--safe-bottom` cleanly before first paint and on `onPageFinished`.

3. **REST API Contract Mismatch on `/api/memories` and `/api/messages` (`web/app.js`)**:
   - **Root cause**: Server serializes `MemoriesResponse` and `MessagesResponse` lists under `.items`, while `syncAllData()` read `.memories` and `.messages`.
   - **Fix**: Read `memoriesData?.items || memoriesData?.memories || []` and `messagesData?.items || messagesData?.messages || []`.

4. **WebSocket `chat_message` Envelope Unwrapping (`web/app.js`)**:
   - **Root cause**: Server broadcasts `{ message: { ... } }` inside `ev.data` on `chat_message`, causing direct `ev.data` insertion to render `Invalid Date` rows.
   - **Fix**: Unwrap `const msg = ev.data.message || ev.data;` before deduplicating and pushing into `state.messages` + updating `state.events`.

5. **Saved Places GPS Hydration, Modal-In-Place Bell Toggle, Sign-Out State, & Non-Destructive Map Overlay (`web/app.js`, `web/styles.css`)**:
   - Hydrated `/api/pair/state` (`me_location`) before `Add current location` fallback.
   - Updated `openModal()` in-place when already open so Saved Places bell toggles avoid replay flash.
   - Cleared `state.googleAuth` and `myEmail` inside `resetClientSession()` + `persistAndSyncNative()` on logout.
   - Memoized `#map-overlay-root` HTML updates (`__lastHtml`) + desktop `.desktop-rail` updates (`bindNavAndRailHandlers()`) and added `sosHolding` render lock + `touch-action: none` so background syncs cannot cancel 2s SOS holds or mid-tap controls.

6. **FigCraft v2 UI Alignment Across Mobile Web, Desktop (`1280x820`), and Android WebView (`web/index.html`, `web/styles.css`, `web/app.js`)**:
